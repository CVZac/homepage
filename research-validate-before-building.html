商业验证Business validation2026年11月23日Nov 23, 2026

写第一行代码之前，先验证需求Validate demand before you write code

做出一个产品，从来没有像今天这样容易。也正因为这样，做出一个没人要的产品，也从来没有这样容易。It has never been easier to build a product. For the same reason, it has never been easier to build one nobody wants.

  2. AI 改变不了什么What it does not change
  3. 一个可以照做的顺序A sequence you can follow
  4. 两个常见的错Two common mistakes

AI 改变了什么What AI changes

AI 让「试一次」的成本大幅下降。AI brings the cost of one more try down sharply.

  • 整理访谈。几十段访谈记录，可以很快归纳出反复出现的抱怨。Interview synthesis. Dozens of interview notes can be sorted quickly into the complaints that keep recurring.
  • 起草方案。同一个提议可以写出许多版本，各自强调不同的好处。Drafting offers. One proposal can be written in many versions, each stressing a different benefit.
  • 预演反对意见。让模型扮演挑剔的客户，提前找出最难回答的问题。Rehearsing objections. A model playing a demanding customer surfaces the hardest questions in advance.
  • 做样品。一个可以点击的样品，一天之内就能做出来。Making a mock. A clickable mock can be made within a day.

AI 改变不了什么What it does not change

模型不是你的客户。问它「客户会喜欢吗」，得到的是一段听起来合理的话，不是证据。它没有预算，不用向老板解释为什么买，也不会在周一早上把你的产品忘掉。A model is not your customer. Ask it whether customers will like something and you get a plausible paragraph, not evidence. It has no budget, no manager to justify a purchase to, and no Monday morning on which to forget your product.

能证明需求的，只有真实的人做出真实的举动：付款、签字、留下联系方式、把同事拉进来。Demand is shown only by real people doing real things: paying, signing, leaving their contact details, bringing a colleague in.

一个可以照做的顺序A sequence you can follow

  1. 写下最危险的假设。如果它不成立，其他都不必谈。State the riskiest assumption. The one that, if false, makes everything else irrelevant.
  2. 选最省的测试。能用一页说明测出来的，就不要做样品。能用样品测出来的，就不要写代码。Choose the cheapest test. If a one-page description can test it, do not build a mock. If a mock can, do not write code.
  3. 先定通过线。在看到结果之前写下：出现什么结果算通过。Set the pass mark first. Before any result comes in, write down what result counts as a pass.
  4. 找真人来测。最好是不认识你、没有理由客气的人。Run it with real people. Ideally people who do not know you and have no reason to be polite.
  5. 按约定作决定。通过就继续，不通过就改或者停。Decide as agreed. A pass means continue. A fail means change it or stop.

两个常见的错Two common mistakes

先看结果，再定标准。结果出来之后，人总能找到理由说它「还不错」。通过线必须写在前面。Seeing the result, then setting the standard. Once a result is in, there is always a reason to call it promising. The pass mark has to be written first.

把礼貌当成需求。「挺好的」不是需求。「什么时候能用」才是。Mistaking politeness for demand. "That sounds good" is not demand. "When can I have it" is.

在写第一行代码之前，先找到一个愿意为它做点什么的真人。Before you write the first line of code, find one real person willing to do something for it.
